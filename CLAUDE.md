# Коло добрих екосправ

Гра для новацтва Пласту: 63 добрі справи для природи по порах року.
101 курінь УСП «Карпатські Вовки». Аудиторія — діти 8–11 років.

## Стек

Статичний `index.html` без збірки і без залежностей (крім шрифтів
Google) плюс Sinatra API поверх Postgres. Деплой — дроплет
DigitalOcean, nginx роздає статику й проксує `/api` в puma.

```
index.html          гра: розмітка, стилі, скрипт — усе в одному файлі
app.rb              API, Sinatra::Base, модульний стиль
config.ru           Rack entry point
db/schema.sql       схема, ідемпотентна
deploy/             systemd-юніт, фрагмент nginx
```

## Доменна мова

Говоримо термінами Пласту, не вигадуємо своїх:

- **новацтво** — діти 8–11; **новак** / **новачка** — одна дитина
- **Рій** — група новаків; **гніздо** — кілька Роїв
- **виховник** — дорослий, що веде Рій
- **сходини** — регулярна зустріч
- **проби** — програма вмінь; гра закриває підрозділ «довкілля»

**Рій** пишемо з великої літери в будь-якій формі: Рій, Рою (не «роя»),
Роєві, Рої, Роїв. В ідентифікаторах коду (`roi`, `grp`) — як є.

У коді й у текстах інтерфейсу — українська. Звертання до дитини на
«ти», речення короткі.

## Модель

`roi` — назва, унікальний чотирисимвольний код, ознака тестового,
`lead_key` — восьмисимвольний ключ виховника.
`novak` — рядок на дитину: `roi_id`, `nick`, `nick_key` (lowercase),
`codes` (jsonb-масив ідентифікаторів справ), `cnt` (генерована з
`jsonb_array_length`), `hidden`, `alias_of`, `updated_at`.
`board` — подання з сумами по Роях, тестові Рої й приховані новаки
виключені.
`vidguk` — відгуки виховників: Рій, прізвисько, справа (`null` — про
гру загалом), назва справи на момент відгуку, оцінка `ok`/`hard`/`fix`,
коментар до 500 символів.

Ключ новака — пара `(roi_id, nick_key)`. Прізвиська унікальні в межах
Рою; про це домовляються на сходинах.

## Рішення, які вже ухвалені

**Код Рою — спільний секрет.** Виховник створює Рій, отримує код,
роздає новакам. Без коду ні прочитати, ні записати поступ. Свідомо:
восьмирічні не заводять облікових записів, а найгірше, що зробить
чужинець із кодом, — припише собі добрих справ.

**Ключ виховника — другий секрет, замість реєстрації.** Видається разом
із кодом Рою, новакам його не дають. З ним (`POST /api/lead*`) виховник
бачить новаків і їхні справи, прибирає й зливає прізвиська, робить
тестовий Рій справжнім. Пошти й пароля немає: загубив ключ — його
дістають із бази вручну. Рої, створені до ключів, мають `lead_key = null`.

**Прибрати новака = приховати.** `hidden = true`: новак зникає з табла
й зі списку, рядок лишається. Справжнє видалення не працює: телефон
дитини дописав би справи назад, і новак повернувся б. Злиття
(`alias_of`) — те саме плюс перенаправлення: записи під старим
прізвиськом ідуть у новий рядок.

**Справжні імена новаків — лише на пристрої виховника.** У «Моєму Рої»
виховник може підписати прізвисько справжнім ім'ям; воно лежить у
localStorage (`st.names`) і на сервер не йде. На сервері — тільки
прізвиська.

**Вік новака — лише на його пристрої.** Новаки не думають пробами й
не знають позначок на кшталт «V.Г.16», тож у «Хто ти?» питаємо роки
двома проміжками: 7–9 і 10–11, бо й текстів у справи два. Вибір лежить
у `st.band` і на сервер не йде. Для 10–11 (IV–V проба) показуємо
текст `o`, якщо справа його має. Пункт проби з
`PROBY` біля справи бачать лише виховник (`st.lead`) і тестовий Рій.

**Merge на стороні бази.** `POST /api/progress` не замінює масив, а
зливає:

```sql
codes = (select coalesce(jsonb_agg(distinct e), '[]'::jsonb)
         from jsonb_array_elements(novak.codes || excluded.codes) e)
```

Причина: дитина грає з телефона й планшета, і last-write-wins з'їдав
би справи. Перевірено на 20 паралельних записах у той самий рядок.

**Без справ новака немає.** `GET /api/progress` рядка не створює, а
`POST` з порожнім масивом лише повертає наявне. Інакше виховник, що
завів Рій, і кожен, хто просто вписав прізвисько, роздували б
лічильник новаків у Рої.

**Тестові Рої.** `roi.test = true` — Рій працює повністю, але в табло
не потрапляє. Щоб виховники перевіряли, не псуючи рахунок справжнім.

**Відгуки — лише з тестового Рою.** Виховники перевіряють справи на
адекватність, граючи в тестовому Рої: під кожною справою в них є
👍 / 🤔 / ✏️ і коментар, а внизу — «Відгук про гру». У справжньому Рої
діти цього не бачать, а `POST /api/feedback` відповідає 403. Читати
відгуки через API не можна — тільки з бази.

**Коди без I, O, S, 0, 1.** Діти плутають їх на слух і на вигляд.

**localStorage як запасний аеродром.** Сервер недоступний — гра далі
працює, поступ лежить у браузері й дописується, коли зв'язок
повернеться. Ніколи не ламай цю властивість.

**Жодного видалення через API.** Стерти Рій чи новака назавжди (скажімо,
на прохання батьків) можна тільки руками в psql.

## Межі

Назва Рою і прізвисько — 24 символи. Не більше 200 справ на новака.
Тіло запиту — 64 КБ. Перевіряється і в коді, і в базі.

## Як запустити

```bash
createdb ekokolo && psql ekokolo -f db/schema.sql
cp .env.example .env            # підстав DATABASE_URL
bundle install
set -a; . ./.env; set +a        # app.rb сам .env не читає
bundle exec puma -p 9292        # API
python3 -m http.server 8000     # статика, окремий термінал
```

`const API = ""` на початку скрипта в `index.html` означає «той самий
хост». Для розробки з двох портів постав `"http://localhost:9292"` і
додай `http://localhost:8000` в `ALLOWED_ORIGINS`.

З `file://` fetch не працює — тільки через http-сервер.

## Правила роботи з цим кодом

`index.html` лишається одним файлом без збірки. Це навмисно: гру має
бути легко скопіювати в інший курінь, віддати іншому виховнику,
відкрити й прочитати цілком. Не розбивай на модулі, не додавай
бандлер, не тягни фреймворк.

Не додавай залежностей без потреби. Поточні: sinatra, puma, sequel,
pg, rackup — і все.

Нові справи додаються в масив `D` у `index.html`. У кожної: пора
року `s`, категорія `c`, складність `lv` (1–3 листочки), емодзі `e`
для наліпки, назва `t`, опис `d`, факт `f` під скретчем, і `tg: 1`
якщо потрібен Рій або дорослий. Необов'язкове `o` — складніший
варіант опису для 10–11 років (IV–V проба); справа та сама, поступ спільний. Ідентифікатори `d1`…`dN`
проставляються автоматично за індексом — **не переставляй наявні
елементи масиву і не видаляй їх**, бо зсунуться ідентифікатори вже
записаних у базі справ. Нові дописуй **у самий кінець масиву**, хоч би
якої пори року вони були: пора задається полем `s`, а вставка в кінець
осіннього блоку зсунула б номери всіх зимових, весняних і літніх справ.

Справи спираються на новацькі проби, розділ Г, підрозділ «довкілля»
(`docs/novacki-proby-2021.pdf`). Що з проб уже покрито, а чого
бракує, — у `docs/proby.md`. Нова справа має закривати конкретний
пункт проб.

Тексти справ пишемо для восьмирічного: одна дія, одне речення.
Факт під скретчем — те, чого дитина не знала, а не мораль.

## Відкриті питання

- `limit_req` у `deploy/ekokolo.conf` стоїть 5r/s burst 20 — цифра
  взята зі стелі. Рій на сходинах часто сидить за одним Wi-Fi, тобто
  за однією IP-адресою; якщо в логах будуть 429 від своїх — піднімати.
- Поступ, що лишився в Google Таблиці від першої версії, у базу не
  перенесено.

## Чого не робити

Не збирай персональних даних дітей. Тільки пластове прізвисько й
назва Рою — ні прізвищ, ні пошт, ні фотографій. Якщо колись
знадобляться фотозвіти, це окрема розмова про згоду батьків.
